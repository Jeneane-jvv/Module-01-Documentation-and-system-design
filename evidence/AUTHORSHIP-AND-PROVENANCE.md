# Authorship and Provenance

## Portfolio ownership

This repository represents **Jeneane van Vuuren's own software-engineering learning, practical work and professional portfolio development**.

I provided my original completed work and learning evidence from my Documentation and System Design training, including my own assignment work, notes, diagrams, design thinking and practical evidence. These materials formed the foundation from which I reviewed what I had learned and identified what needed to be improved for a professional portfolio.

The public FirstCommit case study is a professional rebuild that applies those skills to one connected system-design concept.

## How AI mentoring was used

I used ChatGPT as an **AI-assisted mentor, reviewer and editing partner** while rebuilding the work for my professional portfolio.

The mentoring process helped me to:

- review and better understand my original work;
- identify weaknesses, inconsistencies and gaps;
- improve the way I ask engineering questions;
- separate problems, evidence, assumptions, requirements and solution ideas;
- improve documentation structure and professional wording;
- review requirements and traceability;
- refine Mermaid diagram source and visual layout;
- identify and correct DFD, ERD and wireframe inconsistencies;
- validate that the different design artefacts describe the same system;
- organise the final repository for professional GitHub presentation.

I did not simply accept every proposed change. I opened the project in VS Code, reviewed the editable source, questioned design choices, requested corrections where something did not make sense or was not readable, checked the live rendered diagrams and approved the final versions.

## Original work and professional rebuild

My original training work was used as **evidence of skills I had already practised**.

The final GitHub project is not a copy of an assessment submission. It is a new professional case study that demonstrates how I now apply those skills more deliberately.

The repository therefore reflects:

**My original learning and practical work → review and mentoring → corrections and deeper understanding → professional rebuild → validated portfolio evidence**

## What is not presented as my original work

The public repository does not present the following as work created by me:

- lecturer or training-provider documents;
- assessment briefs or marking rubrics;
- supplied model answers;
- another student's work;
- third-party application code;
- downloaded portfolio templates.

Where training materials were consulted, they were used only to understand the competencies and context of the work I had completed.

## Accountability

I remain responsible for the final portfolio and for being able to explain the design decisions represented here.

My standard for publishing the project is:

> **If I cannot explain why an element exists, how it connects to the rest of the system, what problem it addresses, and what I would improve, it is not ready to represent my work.**

## Authorship statement

The most accurate description of this repository is:

> **Jeneane-owned and Jeneane-reviewed software-engineering portfolio work, built from my original practical learning and completed work, and professionally refined through AI-assisted mentoring.**
